在按下电源键后，电源开始向主板以及其它设备供电。起初由于电压还不稳定，主板芯片组会持续地向中央处理器（CPU，Central Processing Unit）的 reset 引脚输出高电平，直到电源能够稳定供电。在这一阶段中，CPU 一直处于初始化状态。该状态下的 CPU 处于实地址模式（Real address mode），其内部的 cs:ip 寄存器的值为 0xf000:0xfff0。

<!--more-->

## 基本输入输出系统（BIOS，Basic Input/Output System）

{% note info %}
如今传统 BIOS（Legacy BIOS）正逐步被淘汰，新推出的 UEFI 更加标准化，更加安全且有图形配置界面。但是出于简单性考虑，本文仍然基于 Legacy BIOS 进行讲解。
{% endnote %}

当主板芯片组撤销 `reset` 信号后，CPU 开始从内存地址 0xffff0 处逐条地执行指令。这一段内存空间存放了 BIOS 的代码。它主要负责设备自检、设置中断向量表（IVT，Interrupt Vector Table）以及填写中断例程。

![](2023-09-08-0338.png)

你可能会有疑问：BIOS 是何时被加载到内存中的呢？ 如果实际安装的 “内存条” 没有 1 MiB 会怎么样？

内存是指能被 CPU 直接寻址的存储设备。除了 “内存条” 外，主板上存储 BIOS 代码的只读存储器（ROM，Read Only Memory）也是内存的一部分，也可以被 CPU 直接寻址。ROM 是非易失性存储器，不会因为断电而丢失数据。主板厂商在主板出厂前就将 BIOS 代码写入到 ROM 中了。因此，不需要加载 BIOS 到内存中，因为它本身就在内存中。

{% note info %}
“内存条” 的专业名称是：动态随机存取存储器（DRAM，Dynamic Random Access Memory）
{% endnote %}

## 主引导记录（MBR，Master Boot Record）

BIOS 是启动流程的第一个环节。下一环节的代码在哪儿？怎么加载到内存中？都要由 BIOS 解决。

这里涉及到了 BIOS 协议 —— 如果一个存储设备的第一个扇区以 0x55 和 0xaa 结尾，那么称该扇区为 MBR，有 MBR 的存储设备就是可启动的。BIOS 会查找可启动的存储设备，并加载 MBR 到内存地址 0x7c00 处。然后转交控制权。

![](2023-09-08-0339.png)

{% note info %}
1. 扇区原本是磁盘上的物理概念，是磁盘读写最小的单元，其大小通常为 512 字节。出于兼容性的考虑，闪存在逻辑上也有扇区的概念。

2. 0x7c00 最早出自于 IBM PC 5150 的 BIOS 中。根据其开发者 Dr. David Bradley 所述，虽然该机型有 16 KiB 内存的版本，但是运行 DOS 1.0 至少需要 32 KiB 内存。又因为内存低端 1 KiB 是中断向量表，因此 MBR 被加载到了内存高端位置，多余的 512 字节作为栈使用（0x7c00 = 32 KiB - 512 B（MBR） - 512 B（栈））。
{% endnote %}

## 引导加载器（Boot Loader）

MBR 只有一个扇区的大小，这么小的空间无法容纳一个完整的操作系统（OS，Operating System），因此需要有一个程序为 OS 提供运行环境、加载 OS 并转交控制权，这就是 Boot Loader。

即使 Boot Loader 已经尽可能小了，往往也会超过一个扇区的大小。因此 Boot Loader 一般会分为两到三个阶段（Stage），逐级自行加载。

至此，计算机由 OS 接管，启动流程结束。
